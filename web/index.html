      Why switching resets the chat
      
Changing AI source restarts the agent on a different engine, which
        ends its current conversation, wherever you talk to it (web chat, console or Telegram). With this on, the agent first writes a short summary of what you've

        kept either way — this is only about the current chat.

      🎙 Voice & media — shared key for Telegram voice notes
      

        A Gemini API key can provide transcription for Telegram voice notes:
        audio is sent to Gemini, then the agent answers using its own AI source.
        Get a key at aistudio.google.com.
        Saving does not test the key or change running agents. Existing agents receive it on their next
        Rebuild, unless their Gemini AI source supplies its own key.
        Browser Talk uses separate voice settings. After Rebuild, the agent's
        Advanced → Voice → Set up Talk can use this key for Google voice.
        Setting it up does not start a call. Shared credential:
        available to agents across this server, so anyone who owns an agent here
        can use it (and a technical user could read it). Use a key scoped to this
        purpose, not a personal all-services one.
      

      

      

        
        
        
      

    


    

      🔎 Fleet search key — a Brave key upgrades every agent from DuckDuckGo
      

        Every agent has web search built in (keyless DuckDuckGo). Paste one
        Brave Search API key
        here and the whole fleet upgrades to Brave on each agent's next
        Rebuild — better results, proper rate limits. A per-agent
        BRAVE_API_KEY env var overrides it (its own quota).
        When the key runs out, agents move to DuckDuckGo by themselves and back when
        its quota returns, with no rebuild. Hatchabot checks every few hours, spending one query each time.
        A new key reaches each agent at its next Rebuild; until then it uses DuckDuckGo, even if the old key still works.
        Shared credential — same caveats as the media key.

What Restore does & where sets live
      
Restore rolls a single agent's whole volume back to that night (more than a
      snapshot, which only reverts SOUL/AGENTS/MEMORY) — it overwrites live memory, so the agent is stopped for
      the swap and restarted after. Each set holds bot tokens and the decryption key in the clear, so it lives in
       at 0700 and is never downloadable from
      here.

    

    
Backing up, restore drills and the nightly sets are run by this machine's owner.
      Below: whether each of your agents could be brought back.

    

      
    

    

    
Can each agent be brought back?

    
For each agent, the newest backup a restore could use, and the last restore drill that checked it.
      A drill restores each agent's copy into a throwaway volume with no network, then removes it — nothing live is touched.

Good to know

  
A few concepts that aren't obvious at first.


  

    

      Changing an agent
      
    
        
  • Model changes are instant — pick a model and it takes effect on the next message. No rebuild.
    • 
        
  • Most other changes apply on the next Rebuild — AI source, data, environment, rich messages, peers. The agent's card says so.
    • 
        
  • A plain Rebuild keeps your conversation (it resumes). Only switching the AI source starts a fresh thread — and that offers "Save conversation to memory first."
    • 
      

    


    

      Memory & the model command
      
    
        
  • Memory is shared: an agent has one memory for everyone who talks to it. For something private, give that person their own agent.
    • 
        
  • Agents write durable facts to memory as they go. Chat → Memory saves the current conversation on demand — handy before a source switch or a long archive.
    • 
        
  • Typing /model to the bot in Telegram is a temporary this-conversation switch — it reverts. Change models in the app to make it stick.
    • 
      

    


    

      Archive & limits
      
    
        
  • Archive keeps everything the agent learned and hands its bot back to the pool. Restoring gives it a new bot & link to reshare. Save to memory first before a long archive.
    • 
        
  • Archived agents don't count toward your agent limit, and settings changes reach them when you restore.
    • 
      

    


    

      Google connections
      
    
        
  • Reconnecting an account detaches its agents — always reconnect, then re-attach it.
    • 
        
  • Each Google service (Sheets, Docs, Contacts…) must be enabled once in your Cloud project — separate from approving the scope.
    • 
      

    


    

      Talking & safety
      
    
        
  • Agents can consult each other — the agent's Sharing tab (same-owner only; needs a rebuild, since it installs a tool).
    • 
        
  • Anyone you admit, on any app or on the web, can direct it. Be mindful of powerful agents (that send email or write files) with a wide audience — ⚙ → 🛡 Security shows each agent's exposure.
    •

⚡ Bulk actions

  
Pick a set of agents, then an action. Selection filters just tick the list for you — adjust by hand after. The Hatchabot manager is never in the list; it is handled on its own.


  
  


  

    
    
  

  


  
  

    
    
    
    
    
  

  

    Rebuild at once 
    — rebuilds beyond this wait their turn (the machine's setting, also under Settings → Hosts).
  

  

    
  

  

    
    
  

  

  

  


  

  

  

    Rebuild everything
    A new container for every running agent, memory kept. Picks up a new runtime image or network. Stopped and sleeping agents are rebuilt when they next start.
  

  

    Check every agent
    Asks each running agent whether it answers, and checks its settings for mistakes — one at a time, a few seconds each. What it finds shows on the agent's icon and under View by → Alerts.
  

  

    
    
  




  
Try  on…

  
 — pick the agents to pin to this image. Running ones rebuild now (memory kept); stopped and sleeping ones stay that way and move onto it when they next start. Each stays on it until you discard the trial; every other agent keeps the fleet default.

  

    
    
    
  

  

  

  

    
    
  




  
Migrate all agents off 

  
Host-owner action. Every agent on this source — including other accounts' — moves to the shared source you pick. Running ones rebuild (as many at once as Rebuild-at-once allows); stopped and sleeping ones are not started, and take it when they next start. Then the old source can be deleted.
