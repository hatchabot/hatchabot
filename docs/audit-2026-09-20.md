# Audit — 2026-09-20 (22nd)

Scope: the fifteen releases of 2026-09-19/20 (v1.36.0 → v1.51.0) and a
screen-by-screen pass over the whole app, plus documentation, the website and
the deck. Method: read the diff; open every screen and dialog under a stubbed
`fetch` and collect JS errors; hunt dead code and unescaped interpolation; run
the unit suite, the typecheck and the in-process end-to-end flow.

## What was checked, and with what

| Check | How | Result |
|---|---|---|
| Every screen opens without a JS error | 60 steps through the real `web/index.html` under a stubbed fetch, collecting `window.onerror`, unhandled rejections and `console.error` | **clean** — every settings tab, agent tab, fleet panel and dialog |
| Unit + integration | `npm test` | **1226 pass**, 123 files |
| Types | `tsc --noEmit` | clean |
| End-to-end lifecycle | `npm run e2e` (mock provider: profile → host → bot → provision → boot → RUNNING, then the rollback path) | pass |
| Unreferenced code | every `function` and exported symbol in `src/` and `web/` cross-referenced against the tree, tests and scripts | one dead function, no dead modules (below) |
| HTML injection | every `${…}` added today inside an `innerHTML` template, checked for `esc()` | clean — the three that skip it are escaped by their helper, or go to `textContent` |
| Swallowed failures | every function returning `{ ok: false }` traced to its callers | one real bug, found and fixed (below) |
| Menu copy | every `.sub` block over 120 characters, ranked | six more trimmed |

## Found and fixed

1. **A literal `X` in the Machines tab** where each machine's agent count
   belongs — a careless one-line edit in v1.36.0 replaced the whole span with
   the letter, and no test looks at that string. Restored in v1.51.0. The
   screen-by-screen pass is what caught it; the lesson is the one from the
   morning's release gate — every scripted edit asserts its anchor.
2. **Deleting a derived image forgot it when Docker refused** (v1.49.1). The
   removal resolves `{ok:false}` rather than throwing and the route ignored it,
   so a failed `docker rmi` — a stopped container still referencing the image is
   the usual cause — dropped the row, reported success and left a 2GB image with
   nothing left to delete it from. This produced the day's orphaned
   `ch3-traceroute`. The row now survives and Docker's reason is reported.
3. **A derived image whose row was already gone could not be deleted at all**
   (v1.48.0): the tag route refused every `:derived-*` tag to keep deletion on
   the path that also forgets the Dockerfile. It now refuses only while the row
   exists, and a leftover deletes as an ordinary tag.
4. **A dead pool bot renamed itself every five minutes, forever** (v1.44.0):
   Telegram's `Unauthorized` was treated like a rate limit. One was doing this
   on the author's box.
5. **Dismiss did not stick** on a failed change (v1.49.1) — it lived in memory,
   so a reload brought the card back.
6. **"More" appeared on text that had no more** (v1.51.0): the two-line clamp
   added the button by character count rather than by actual overflow.
7. **Notes to the management agent are capped** at three waiting behind a
   running turn, so a burst of builds finishing together cannot queue an hour of
   conversation.

## Dead code

- `activityResizer` in `web/index.html` — the only function in the app nothing
  calls. Left for now; it is three lines and the resize bar it belongs to is
  still in the classic view.
- **The legacy Telegram management bot** is the one real removal candidate:
  `src/mgmt/bot.ts`, `index.ts`, `notifier.ts`, `proposalNotifier.ts` and
  `deploy/hatchabot-mgmt-bot.service` (~1,100 lines). Everything else under
  `src/mgmt/` is the shared broker the web chat and the Hatchabot agent both
  use, and must stay. The bot is marked legacy in the app and the docs and is
  retired on this machine; removal is a decision, not a cleanup, so it waits.
- 127 exported types read as "unused" to a crude scan; all are annotations
  inside their own file or deliberate API shapes. No action.

## Still open (carried forward)

- **42 of 45 agents have never been rebuilt onto the isolated docker network**
  (from the 18th/19th audits). One "Rebuild all" clears it.
- **Ollama listens on every interface, unauthenticated**, reachable from the
  LAN and the tailnet. Bind it to loopback plus the docker bridge.
- **Hatchabot binds `0.0.0.0:8080`** although access is meant to be through
  Tailscale serve (tailnet-only, verified). Loopback would be tighter.
- **An unidentified listener on `0.0.0.0:4000`**, owned by another user:
  `sudo ss -ltnp sport = :4000`.
- **Slack and Discord have never been exercised against real apps.**
- **The older built-in management chat has not been retired** — deliberate,
  pending real use of the agent.
