# Audit — 2026-09-21 (24th audit)

Scope as asked: a code audit, a security review, documentation (docs, deck
and PDF, website), and a recap of what is outstanding — especially what
blocks a beta release. It covers everything since the 23rd audit
(**v2.8.1 → v2.30.0**: 36 releases, 38 commits), most of it driven by the
first install on a clean machine (a MacBook).

## 2. Code audit

**Route surface since v2.8.1** — 13 added, none removed:

| Route | Guard |
|---|---|
| `GET /v1/agents/:id/known-people`, `POST …/members/known`, `POST …/members/:userId/reopen`, `POST …/allow-knocks`, `POST …/channel/swap` | `ownedAgent` |
| `POST /v1/ai-profiles/:id/move` | owner of the profile (404 otherwise) |
| `GET /v1/bots/:username/token` | machine owner, logged |
| `GET /v1/tailscale`, `GET …/qr.svg`, `POST …/serve`, `POST …/use-for-links` | machine owner |
| `POST /v1/auth/family-accounts` | machine owner, shared-password mode only |
| `POST /v1/local-accounts/:id/reset-link` | host owner, not for themselves |
| `POST /v1/local-accounts/recover` | **signed out by design** — see §3 |

Every one has tests. The sticky-sort machinery (table, hooks, `GET
/v1/groups/sort`) was removed cleanly when sorting became a one-shot toggle.

**The bug class that mattered most** was found by using it, not by reading
it: `pairing_window.expect` (v2.14.0) was added to a `CREATE TABLE IF NOT
EXISTS` with no `ALTER`, so it reached fresh databases and never the live one,
and took the whole Telegram approve flow down while every test stayed green.
The fix is not just the migration but a gate — `upgrade-check.sh` builds a
database with an old tag's own code and opens it with this one, in CI. It was
verified to fail when that migration is removed.

**First-run on a clean machine** (the MacBook) found nine real bugs, all fixed:
the ops door refusing the doorman on Docker Desktop; a fresh agent's first knock
hidden from its own owner; closing the door with an empty allowlist locking the
owner out; the pairing message that ate the first "hi"; the Tailscale CLI not
found inside the Mac app; "reachable" claimed without checking; the install QR
encoding `localhost`; a loopback `HATCHABOT_PUBLIC_URL` treated as public; and
a red Docker error on the first image pull. Every one was invisible on the
Linux box it was built on.

**Fixed in this audit:** the setup wizard told a Mac user to "leave the token
blank" to use the machine's Claude login, which only works on Linux and made a
source that could never answer. It is now offered only when the machine is
Linux, and refused elsewhere with the command to run instead.

## 3. Security review

**Access to agents (the Telegram door).** Agents rest in OpenClaw's
`allowlist` mode: a stranger who finds a bot gets no reply at all. `pairing`
is entered only while a claim window is open for someone invited, while nobody
is on the list yet, or when the owner chose "anyone can knock" — and the
policy and the list it enforces are always written together. Live on this
machine: every Telegram agent is in `allowlist`. A window can be held for one
named @handle; the handle only matches the knock, and what is stored is the
numeric id, so a handle changing hands later grants nothing.

**Sign-in.** One signed-out route was added, `recover`. It answers identically
— body and, roughly, time — for an unknown username, an account with no
Telegram, and a link actually sent; limits a username to one request per five
minutes, case-insensitively; bounds the memory it keeps; sends a one-use,
15-minute link only to a Telegram id already bound to that account, through a
bot that has talked to it; and does not exist in shared-password mode.
"That's me" — the one tap that grants an identity rather than a seat — asks
first and says the name back.

**Secrets.** Bot tokens can be revealed per agent and per bot in the
inventory: machine owner only, one at a time, logged, no "reveal all".
The `.env` writer replaces only placeholders and loopback values, refuses to
overwrite a real choice, and writes through a temp file with the mode kept.

**XSS.** Every user-controlled string added to the UI since v2.8.1 goes
through `esc()`, `toast()` (textContent), `confirm()` or `.textContent`.

**Signed-out probes on the live install:** `/v1/agents`, `/v1/bots/x/token`,
`/v1/tailscale`, `/v1/pool` and `POST /recover` all return 401.

**Findings, both low:**

1. **`recover` is not reachable on an identity-mode install** — it is exempted
   only in the accounts-mode sign-in hook. It fails closed (401), and matters
   only for local accounts on a Google-sign-in install, which is rare.
2. **The ops door's loopback allowance** (added for Docker Desktop) would also
   apply on Linux if the door ever fell back to binding `127.0.0.1`. Both paths
   through it still require the per-agent key, so it is defence in depth only.

**Host exposure on this machine (operational, unchanged):** Ollama listens on
`*:11434` without authentication; something unidentified listens on
`0.0.0.0:4000`; Hatchabot is on `0.0.0.0:8080` (sign-in required); Tailscale
`serve` is tailnet-only.

## 5. Beta blockers

What has to be true before strangers install it:

1. **A clean install of the final build, on both platforms.** The MacBook run
   was worth nine bugs, and it was of v2.17 — the default sign-in, the door,
   the HTTPS step and recovery have all changed since. One more purge-and-
   reinstall on the Mac, and a first one on a clean Linux machine, of the exact
   tag that becomes the beta.
2. **A freeze.** 36 releases since the last audit, several fixing the one
   before. The beta should be a tag that sits unchanged for about a week of
   real use, so the next migration-class bug surfaces on your machines first.
3. **The host owner with no Telegram, locked out.** Today that means a
   terminal. The recovery code (proposed, not built) closes it: shown once at
   account creation, it lets *Forgot password?* work with no chat app at all.
   Small, and it is the last sign-in path that needs a shell.

Everything else below can ship after the beta.

## 6. Outstanding, not blocking

**Product**
- Slack and Discord against real apps, then unhide (built, behind `?dev`; the
  site and deck now say "next").
- `recover` on identity-mode installs (§3, low).
- Google sign-in needs a verified OAuth client to be zero-setup; with accounts
  as the default it is now the advanced option, not the front door.
- OpenClaw 2026.9.x waits on the shared embedding service.
- Per-agent search providers.
- The Telegram ceiling of about 20 bots per account (documented).
- Installer copy: "Building the runtime image" is printed when it is about to
  pull, not build.

**Operations on this machine**
- Close Ollama to loopback or the tailnet (`OLLAMA_HOST=127.0.0.1`).
- Identify the listener on `:4000`; confirm SSH password login is off.
- Seven other people's agents still run on the old Docker network until their
  owners rebuild them.
