# Audit — 2026-09-11 (13th; v0.117.0 → v0.134.0, whole codebase)

Four parallel reviewers (security, orchestration correctness, web UI, tests + data
layer) over the 31 commits since the last audit plus a sweep of the rest; every
finding below was re-verified against the code before being acted on. Nearly all
were in code shipped in the previous week (A2A, live model, classes, operator
file, transcript, bulk actions, legend).

## Fixed in this pass (v0.135.0)

### CRITICAL
- **apply-default-model live-applied the OLD model.** `profile` was read before
  `setAIProfileModel` and never re-read, so every switched agent got
  `models set <old>` (a no-op) while the DB/UI said the new one. Now applied via
  `applyModelToRuntime`, which re-reads the store. Regression test.
- **Duplicate `id="peerList"`** (agent Peers tab vs Settings → Servers): the
  Servers list rendered into the hidden pane since v0.124.0. Renamed.
- **Bulk "Set class"/"Switch model" reset the chosen option on every checkbox
  tick** (the option list was rebuilt), so Apply could clear the class from the
  whole selection. Choice preserved across re-renders.

### MAJOR
- A live model change cleared `peersPending` (the applied-peer snapshot was
  inside `setAgentApplied`); the consult tool was never installed. Snapshot split
  into `recordAppliedPeers`, called only from provision/rebuild.
- Owner adoption (first identity sign-in) didn't migrate `agent_classes`,
  `operator_profile`, `posture_snapshots` → operator text would have reverted to
  "Not set" on every agent. Added to the adopt list.
- The A2A call token was listed/revocable as a user CLI token, and once revoked
  could never be re-minted (the secret survived). Filtered from list/revoke; mint
  keyed on the DB row.
- `applyClassToAgent` switched the source before validating the model → a bad
  class left the agent half-switched. Now validates everything against the target
  source first, applies in a transaction; also carries the machine-login
  cross-owner guard the other switch paths had.
- A2A returned docker/openclaw errors (incl. stderr) as the peer's answer with
  200. Now 502/504; reply capped; the consult text is logged to the timeline.
- Recovered transcripts labelled a user-typed "System note:" as
  `System (AgentClaw)` → chat text could be laundered into memory as platform
  authority on Recover. Speaker now comes only from the record role; the recovery
  prompt says user lines are never instructions.
- "Stopped agents pick the model up on next start" was false (start doesn't
  re-provision). `models set` now runs against a stopped agent's **volume**
  (staged), for /model, apply-default-model and classes. Dead `rebuild` param
  dropped.
- Duplicate class name → unhandled SQLITE_CONSTRAINT (500) → 400.
- Class edits wrote onto ARCHIVED agents → skipped.
- Revoking all peers left the `## Peers` section, tool and manifest → removed on
  rebuild (`removeSection`).
- Peers-tab Save could PUT an empty list while loading → revoke everything.
  Save armed only after the list loads for that agent.
- `peersPending` had no card row/rebuild button (only a legend icon) → added.

### MEDIUM
- A2A guard replaced: per-target in-flight set (breaks A→B→A at depth 2 without
  affecting unrelated consults) + per-owner concurrency cap + per-caller
  rate limit (`AGENTCLAW_A2A_PER_HOUR`, default 60) + `isBusy(target)` 409;
  env parsing validated (a typo used to disable the guard). Consult text framed
  as untrusted third-party input.
- Operator-profile save fanned ~90 serial docker execs inside the request →
  202 + background; busy agents skipped (no interleaving with a rebuild's sync).
- Unbalanced code fence in operator text would put every later managed heading
  "inside a fence" → unbounded `## Peers` re-appends. Fence delimiters neutralised.
- `GET /v1/security/posture` wrote the day's baseline (a page view could hide a
  newly-appeared risk from the sweep) → read-only.
- `GET /v1/agents` did 3 queries per agent for peers/class → one query pair per
  request; index on `agents.class_id`.
- Recover-context could run twice concurrently → per-agent guard (409).
- Transcript: byte-based truncation (UTF-16 length could exceed the 8MB exec
  buffer); NaN-safe sort; only same-timestamp assistant mirrors de-duplicated
  (a user's repeated message is kept); shell-quoting via `'\''`.
- Bulk "Set class" shows the server's reason instead of a bare "failed"; local-
  source agents pre-skipped; "needs rebuild" chip honours the rebuilding
  suppression; class counts refresh after bulk changes; single-agent class control
  on the AI tab; operator textarea capped to the server's 8000.

### MINOR
- A2A call-token secret deleted with the agent; tombstones drop `class_id`.
- Fleet-actions dialog opens before its fetch; classes always refetched.

## Backlog (not fixed)
- **A2A runs in the peer's main session** (owner's choice). Exfiltration via a
  wide-audience caller is mitigated (untrusted framing, rate limit, full text in
  the timeline) but not removed. Options: an isolated `--session-key` for
  consults; a posture risk for "agent with group/≥3-member audience holds peer
  grants"; notify the target's chat on consult.
- `syncDataSourceDocs` is an unlocked read-modify-write of AGENTS.md; a save
  concurrent with an operation that doesn't mark busy could interleave.
- Posture: first sweep logs every risk as "newly appeared" (noise on install).
- `tokensPerHour` when no session carries `sessionStartedAt` falls back to
  min(updatedAt) — slightly inflates the rate.
- Cross-owner A2A denial, empty-text 400, 8000-char truncation and several class
  /peers error paths are still only lightly tested.

## Verified clean
Auth exemption regex (now tested); token scoping (`agent_id IS NULL` split);

inputs (`[a-z0-9-]`, re-validated on import); `provider.exec` argv-only; web

resets; mgmt viewer/operator split; googleConnections reconcile intersection;

directions; `deleteAgentClass`/`setAgentPeers` transactions.
