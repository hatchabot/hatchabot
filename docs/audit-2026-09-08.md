# AgentClaw — 12th comprehensive audit (2026-09-08)

Whole-codebase pass (~23k LOC) run as six parallel adversarial reviewers, one per
subsystem, each finding then verified against the code before fixing. Baseline:
v0.116.1 (11th audit was 2026-09-06 @ v0.112).

**Headline: no CRITICAL. One MAJOR — a pre-existing, documented accepted risk.
The rest MEDIUM/MINOR.** The isolation model, escaping discipline (web), and
shell-injection guards (slug/email validation) held up well under scrutiny.

## Backlog (not fixed — ranked within tier)

### MAJOR (accepted risk — close before multi-tenant)
- **Shared machine-login Max mounts another owner's `~/.claude`** (routes.ts create + profile-switch). Gated behind a `shared` profile and documented `⚠ ACCEPTED RISK` (docs/pre-production.md). The concrete close: require a `secretRef`/setup-token before a shared subscription profile is usable by a non-owner.

### MEDIUM
- ~~**connections:** `syncConnections` adds but never removes~~ — **FIXED v0.118.0.** Rebuild now enumerates the container's gog accounts and dematerializes any that are in the owner's vault but no longer attached; scoped to vault emails so a self-connected account is untouched.
- **orchestrator:** move/import don't run `runRebuildHook` — tools installed outside `$HOME` (apt, /usr/local) aren't reconstituted on the target until a full rebuild.
- ~~**mgmt:** bot gates *who* issues commands but not *where output goes*~~ — **FIXED v0.118.0.** `onMessage`/`onCallback` now ignore group chats (negative Telegram chat id), so fleet data never renders where non-members can read it.
- **mgmt:** flat allowlist, no roles; `/mode readwrite` and `/pause` are global mutable state — any allowlisted id can arm mutations (or pause management) for everyone. Split viewer vs mutate-owner tiers.
- **channels:** `telegramPool.provision` TOCTOU — the existing-lease check isn't atomic with the claim CAS, so two concurrent provisions of one agent can lease two bots (orphaned lease + double poller). Single atomic statement or UNIQUE on `leased_to`.
- **mgmt:** approve/deny-join buttons trust unsigned Telegram `callback_data` and skip the confirm + read-write gate — an allowlisted (or compromised) client can forge `apr:<agentId>:<code>`. Re-verify the pair against the pushed pending set. (Contained to the owner's own fleet.)
- **providers:** host-folder mounts have no path allowlist/containment (owner-chosen absolute `hostPath`, RW when `rw`). Accepted household risk; add provider-level containment before multi-tenant.
- **orchestrator:** `inspect.ts`/`snapshots.ts`/provider trust `runtimeRef`+`slug` with no in-module ownership re-check. Routes gate today; pass/assert `ownerId` at the orchestrator entry as defense-in-depth.
- **store:** `listEvents` builds one bind var per visible agent (`agent_id IN (…)`) — exceeds SQLite's variable cap at large fleet size. Chunk or filter by `owner_id`.

### MINOR
- store: `deleteConnection` (2 statements) and `scrubAgentResidue` (7 statements) aren't wrapped in a transaction (scrub self-heals on boot).
- secrets: `ref` not bound as GCM AAD (out of current threat model).
- api: invite/join endpoints unthrottled (confirm invite-code entropy ≥128-bit); `GET /` reads the SPA from disk per request + per-request QR regen (cheap DoS lever).
- providers/templates: `JSON.stringify`-as-shell-quoting in snapshots/template (safe only via slug validation — switch to the single-quote helper); volume-name collision possible on shared slug + 8-hex agent-id across owners; stale `gzip -t` comment in `importWorkspace`; cron/schedule re-import non-idempotent; `importState` tar-prefix detection brittle for foreign archives.
- channels: house-bot recycle DMs prior chatters the new (cross-owner) agent name; unbounded recursion on lease contention; `asSelf` owner-binding derives from a claimed identity (safe only because owner-initiated); bot token sits in fetch URLs that feed logged error strings; slash-command read args skip the schema's numeric bounds.
- web: `esc()` isn't a URL sanitizer for `deepLink` `href` (allowlist the scheme); handler id args not `jsq()`'d (hardening); send-agent `<datalist>` enumerates every account email (confirm intended for identity mode).

## Verified clean (preempt re-investigation)
- Per-owner authorization on the API: `ownedAgent`/`visibleAgent`/`ownsLocalHost` consistently applied; `importTemplate` re-validates `aiProfileId`/`hostId` ownership; attach/detach require both connection-owner and agent-owner. No novel cross-owner path.
- `GET /v1/connections` leaks no `secretRef`/token and filters DELETED agents.
- OAuth callback `page()` and the entire web UI: no XSS — every user/agent-controlled interpolation is `esc()`/`jsq()`'d.
- Shell injection: email + slug validation (`^[A-Za-z0-9…]$`, `[a-z0-9-]`) closes the interpolation sinks; docker calls use argv (execFile), not a shell.
- Migration additive-ALTER loop swallows only `duplicate column name`; timestamps are ISO-UTC so lexicographic staleness compares correctly; secret store uses a fresh IV per put with verified auth tag.
- Move/transfer historical data-loss paths remain correctly ordered (flip host only after import lands; retire source only after target healthy; rollback onto untouched source).
