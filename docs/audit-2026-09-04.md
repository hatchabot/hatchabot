# Audit — 2026-09-04 (9th)

Six parallel auditors over the v0.93.0→v0.98.x churn (web management chat,
host-CLI LLM backend, env travel, group access, cron creation, HTTPS) plus a
whole-codebase security sweep and read-only production checks. Every finding
verified with file:line evidence; the critical ones reproduced empirically.
Same-day fixes shipped in v0.99.0. Prior audits: docs/audit-2026-09-03.md.

## Fixed same-day (v0.99.0)

**Two independent CRITICALs, both in the host-CLI backend:**
- **The spawned `claude -p` had Claude Code's own tool surface live.** Print
  mode executes Read/Glob/Grep and read-only Bash with no permission grant,
  the child's cwd was the install dir (beside `.env` holding the secret-store
  MASTER KEY), and it inherited the control plane's full environment — a
  prompt-injected management chat could read every fleet secret as the host
  user. Locked down and re-verified live: `--tools ""` (no built-in tools —
  settings allow-rules then have nothing to enable), `--strict-mcp-config`
  (no MCP), `--no-session-persistence` (no transcript files), scratch cwd
  (0700, beside the DB), minimal env allowlist (PATH/HOME/TERM/LANG + the
  setup-token when applicable; never the control plane's secrets). Measured:
  `--bare`/`--setting-sources ""` would be stricter but sever the CLI's
  login; the residual (the host user's own settings hooks) is owner config,
  not attacker surface. Tool results in the flattened prompt are now fenced
  (`<<<TOOL_DATA … TOOL_DATA>>>`) against role-spoofing.
- **An unhandled stdin EPIPE could kill the whole control plane** (reproduced:
  fast-exiting child + >64KB buffered prompt → uncaughtException). One
  `stdin.on('error')` handler; regression test spawns /bin/true with 4MB.

**Majors:**
- **A cleared group-access setting left a stale open room on the volume**:
  the config write was guarded by `if (groupAccess)`, so clearing back to
  default skipped the converging rewrite — non-members of the once-open room
  kept access while the UI said members-only. The group block now writes
  unconditionally.
- **History cap broke the Messages-API grammar**: `slice(-30)` could open the
  window on an orphaned tool_result (hard 400 → session permanently broken on
  api-key sources) or end it mid-exchange. `sanitizeHistory` trims both ends
  to legal boundaries; tested including the degenerate cases.
- **Concurrent chat POSTs silently lost a turn** (both raced on the session's
  history; Enter bypassed the disabled Send button). Server: per-session busy
  → 409; web: Enter guard.

**Minors:** web-session PendingStores now swept every 60s (resolved authoring
cards carry multi-KB specs); session eviction is LRU (was FIFO — could drop
the busiest owner's armed session); ambient `CLAUDE_CODE_OAUTH_TOKEN` no
longer hijacks the machine-login flavor; scratch HOME derives from
`AGENTCLAW_DB`'s directory (the invented `AGENTCLAW_DATA_DIR` knob is gone);
a non-string CLI `result` no longer surfaces the raw JSON envelope as prose;
`/group-chats` returns 404 (not 409) for foreign/missing agents;
`AGENTCLAW_CLI_TIMEOUT_MS` override for the 180s CLI timeout.

**Hygiene:** dead `mgmtComplete` binding removed; `ENV_NAME_RE` now actually
imported at both former inline sites; `GroupAccess` imported from
domain/types in provider.ts + store (was declared three ways); the web
proposal card shows Persona in the full-content expandables (a >200-char
persona was clipped despite the full-spec promise); `maxlength` on the five
new inputs; straight quotes in new error strings; `claude-sonnet-5` default
still ×3 in mgmt/index.ts (left — cosmetic).

**New tests (24):** CLI lockdown flags/env/cwd, credential flavors, output
variants, fenced tool results, EPIPE survival; sanitizeHistory grammar cases;
concurrent-POST 409; materializeEnvValues failure → full rollback;
inbox-accept with env-target values; group-access convergence-on-absent; new
drift guard for the 30s/90s heartbeat cadence pair. 786 total.

**Docs (10 findings fixed):** agent-environment.md tasks-can-be-created;
sharing design header vs its own body on 2b; management-broker.md detached
confirms + web transport + per-session arming; control-interfaces.md
non-Anthropic exclusion wording, CLI lockdown + `AGENTCLAW_CLAUDE_BIN`/
`AGENTCLAW_CLI_TIMEOUT_MS`, ambient `ANTHROPIC_API_KEY` fallback, mgmt-chat ≠
member-chat clarity note; features.md version stamp, garbled authoring
sentence, Members-list location, `deny` in the CLI list; moving-agents.md now
states env values travel in the archive; 09-03 backlog annotated with
closures; llm.ts prompt no longer claims Telegram-only.

## Backlog (verified open, ranked)

1. **`POST /v1/join` still has zero HTTP tests** — the unauthenticated,
   internet-facing surface; the last untested item of the 09-03 route list.
2. **mgmt-chat turn can outlive the HTTP connection** (worst case 6 steps ×
   180s > Node's request timeout): the turn completes server-side but the
   response — including proposal cards, which aren't in the transcript — is
   lost to the client. Fix direction: persist proposals into the transcript
   or poll for pending cards on pane open.
3. **CLI prompt path remains a weaker injection boundary than the API path**
   (flattened roles, now fenced but still text); prefer an api-key source
   when one exists (already the pick order) and revisit if the CLI grows a
   structured tool-use output mode.
4. `data/` dir is 775 — other local users can list filenames (contents 0600).
   Tighten to 700 at boot. `data/tls/` (empty) and `data/server.log` (stale
   since July) are deletable artifacts.
5. `adoptLocalOwnerData` re-key list still misses mgmt_heartbeat,
   telegram_pool.owner_id, agent_shares, derived_images (latent — this box is
   past adoption).
6. buildRuntimeSpec ↔ groupAccess joint test (typed edge, low drift risk);
   `everyMinutes` cron branch has no caller and a redundant unit round-trip;
   mixed text+tool_use responses only implicitly covered on the api path.
7. mgmt LLM status rendered three ways (GET /v1/mgmt/llm, GET /v1/mgmt/chat,
   the heartbeat label) — consolidation candidate, not a defect.
8. Sleep-based detached-confirm tests could flake under CI load (vi.waitFor
   would harden); image/authoring HttpApiClient methods never exercised
   against real routes.
9. Carried from 09-03 and still open: shell-quoting hardening
   (JSON.stringify), 3 diverging .env parsers, ~8 undocumented env vars,
   agent_events written post-delete, /mode global arming note (now
   Telegram-only), files-route size caps, writeCoreFile dedup, base-image
   literal ×3, pre-production.md gates before untrusted users.

# Round 10 (same day, evening): v0.100.0 → v0.105.0 feature burst

Scope: the six versions shipped since the morning audit (fleet search key,
lineage/derive/push, distillation, template schedules, group access, members
panel, cron edit, Connections tab, datasource targets) — four parallel review
lenses (lineage/template, route security, web UI, provision/config fleet
safety) + live-state verification. All fixes below shipped in v0.106.0 with
regression tests (819 passing).

## Fixed (v0.106.0)

**Critical**
1. `/v1/inbox/:id/accept` forwarded caller-supplied `aiProfileId`/`hostId`
   into `importTemplate`, which resolved them with the UNSCOPED
   `getAIProfile`/`getHost` — any share recipient who learned a profile UUID
   (leaked via `publicAgent` to member-visible viewers) could bind a new
   agent to another owner's Max subscription and bill it, or provision onto
   another owner's host. Fixed in `importTemplate` itself (own-or-shared
   profile, own-usable host) so every import path is covered.

**Major**
2. push-definition rendered children from the master's LIVE files; a master
   that filled its own setup values (the supported /params master-seeding
   flow) pushed ITS values over every child's and froze placeholder-free
   text as each child's layer. Now prefers the master's raw `paramFiles`
   layer; live files only when no layer exists. Also pushes the master's
   current field declarations to children (a field added after derive shows
   up in the child's values panel instead of rendering as literal {{key}}).
3. push-definition clobbered each child's platform-maintained
   "## Data sources" section with the master's. Each child's own section is
   now spliced back in (new fence-aware `extractSection` in workspace.ts).
4. Proposal merge appended the distilled block to the master's RENDERED
   AGENTS.md read-back as its template layer — placeholders gone. The block
   now appends to the raw layer directly. Merge is also claim-first (atomic
   pending→merged before the write; reopened on write failure), closing the
   concurrent double-merge append.
5. Two-materializer rollback orphaned `agent-env/*` secrets forever when the
   deploy-key write failed after env secrets landed — merged into one
   `materializeImportEffects` with a single rollback list.
6. Clone was impossible for any agent with a required no-default field
   (= every required datasource field): clone now imports leniently with the
   source's own paramValues (a faithful copy needs no re-answers).
7. Distill had no cap: a child's owner could flood a different owner's
   master with unlimited 20KB proposals. Capped at 3 pending per child.
8. Schedule application (step 7.95) re-added ALL parked schedules on retry
   after a partial failure — duplicates survived rebuilds and fired forever.
   Now dedupes by name against `listCrons` and drops applied entries
   individually. Feeder bug: `everyMs` rounded to whole minutes, so a 20s
   interval became `--every 0m` (rejected by the pinned CLI = permanent
   failure keeping the batch parked). New seconds-accurate `msToEvery`.
9. Web: lineage rendering was direct-children-only — a clone of a child
   (grandchild) got NO card and NO TOC entry: running, holding a bot slot,
   unmanageable. Both renderers are now recursive with cycle guards and a
   flat-render fallback.
10. Web: `cronEditingId` never cleared on dialog close/reopen — a leftover
    edit silently DELETED an unrelated task on the next add (cross-agent in
    the worst case). Every open resets to add mode; an "Editing X — cancel"
    note shows; interval/one-shot tasks refuse ✏️ (the form is cron-only and
    would silently convert them).
11. LIVE: `gog auth remove` refuses non-interactively without `--force` —
    the v0.105.0 Disconnect button always failed in production (found by
    probing the real binary; mocks can't catch this class). Fixed +
    leading-dash email refusal + `--` separator (flag-injection guard).

**Minor** — files GET compared UTF-16 chars to a byte cap (multibyte files
truncated mid-char, then saved back truncated) → byteLength; uncapped `cat`
in push/merge → capped with explicit refusal; derive/accept name length caps;
disabled crons no longer travel in templates (came back enabled); runtimeCaps
probes recorded "command not found" as a version for tesseract/pdftotext →
command -v gated; proposals scrubbed on master deletion (tombstone hygiene);
TOC duplicate group headers after a child row; jsq-in-title-attr escaping;
missing encodeURIComponent on cron/proposal ids.
