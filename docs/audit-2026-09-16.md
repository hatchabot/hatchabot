# Audit — 2026-09-16 (16th)

Covers v1.4.0 → v1.9.1: public git sources, A2A mesh, the card reorder rail,
AI-source usage, the OpenAI vendor, accounts mode, the credential reveal, and
the installer/CLI work. Much of this shipped the same day it was audited, which
is exactly why it was audited.

Method: the auth surface by hand; the usage subsystem, the new web UI, and the
published git history each by a separate pass. Every finding below was
reproduced before it was fixed — the ones that could not be reproduced are
listed at the end as *not confirmed*.

## Critical

**1. First-run account creation was open to the whole network.**
`src/api/accountsAuth.ts` — in accounts mode the server binds every interface
(auth is on), but creating account #1 needs no credential by definition. On a
tailnet or shared wifi, the first stranger to load the page could take the
installation: `adoptLocalOwnerData` hands account #1 everything password mode
owned. Introduced by 1.8.0 + 1.8.1 together, neither of which is wrong alone.
*Fixed*: bootstrap is accepted from loopback, or with the setup code the server
prints to its log at startup. Physical/ssh access to the box, or its log, is the
credential.

## Major

**2. A removed account's CLI tokens kept working.**
`src/store/store.ts` — `ownerForCliToken` checks the hash and the expiry, not
whether the owner still exists, so a token minted by an account the host owner
later removed still authenticated as that owner. Removal has to mean revoked.
*Fixed*: deleting an account deletes its tokens in the same transaction, and
accounts mode re-checks the account on every token-authenticated request.
Removal is also now refused while the account still owns AI sources, whose
stored secrets would otherwise have no route left to delete them.

**3. Usage counts could be re-tagged onto another account's source.**
`src/store/store.ts` — `model_call_hours` was keyed `(agent_id, hour)` and the
upsert overwrote `profile_id`, so an agent that changed source mid-hour moved
the whole hour's counts — already recorded under the old source — onto the new
one. Since a source can be *shared across accounts*, that moved one account's
counts onto another's dashboard, steerable on purpose.
*Fixed*: `profile_id` is part of the key (migrated, rows folded), and the upsert
only adds.

## Medium

**4. Rate-limit history vanished the moment you acted on it.**
`src/orchestrator/sourceUsage.ts` — rows and limit hits were filtered by the
agents *currently* on a source. Move a rate-limited agent elsewhere, as the
banner suggests, and its hits disappeared from both sources' views — the one
moment someone would look. *Fixed*: history is gated on ownership; "N agents"
still counts the ones attached now.

**5. A dead Docker daemon looked like an idle fleet.**
`src/providers/localDockerProvider.ts` — `modelCallLog` resolved with `""` on
spawn/stream failure, so the sampler logged nothing, advanced its cursor, and
permanently lost every call made during the outage. *Fixed*: it rejects, the
existing catch logs, and the cursor stays put.

**6. One slow agent could stall a whole sampling pass.**
`src/orchestrator/sourceUsage.ts` — agents were sampled one at a time with a
60 s kill each: 41 agents is 41 minutes worst case, with the next pass and any
manual refresh queued behind it. *Fixed*: bounded concurrency
(`HATCHABOT_USAGE_CONCURRENCY`, default 6) and a whole-pass budget
(`HATCHABOT_USAGE_PASS_MS`, default 5 min) that logs what it did not reach.

**7. Tokens spanning a source switch were charged entirely to the new source.**
`src/store/store.ts` — the diff either side of a switch landed on whichever
source the agent ended on. *Fixed*: an interval counts only when both of its
samples were taken on that source.

**8. Usernames were unique case-sensitively but matched case-insensitively.**
`Chris` and `chris` could both exist while login resolved an arbitrary one.
*Fixed*: a unique index on `lower(username)`.

## Minor

**9.** Account ids were interpolated into `onclick` handlers unescaped. Ids are
server-minted UUIDs, so this is latent rather than live — but it is a trap for
whoever changes id minting. *Fixed*: `jsq()` on both.

**10.** A revealed source credential stayed in the DOM until the list
re-rendered. *Fixed*: cleared when the dialog closes.

**11.** Two 429s from one agent inside the same millisecond collide on
`limit_hits`' key and the second is dropped. Undercount only; left alone.

**12.** `others` on a shared source is counts-only, but with exactly one other
account those counts *are* that account's activity. Accepted for household
sharing; noted so it is a decision rather than an oversight.

## Git history and published artifacts

Scanned every commit reachable from `origin/main` for credential shapes
(Anthropic, OpenAI, Telegram, GitHub, AWS, Google, private keys, CLI tokens,
64-hex secret keys) and for personal data (emails, home paths, tailnet names,
Telegram user ids).

- **No real secrets.** The only matches are four fixture keys of the
  `sk-ant-fake-…` form in tests.
- **Pre-1.0 history is not published.** Those commits exist only on the private
  `archive` remote and local refs; the public remote carries 69 tags and
  **zero** `v0.*` tags, so the scrub held.
- **No absolute home paths** in the tree; every `ts.net` reference is a
  placeholder; no Telegram ids.
- The public history has a single author identity (`ckscijdtest@gmail.com`),
  which is a deliberate separate address rather than the owner's personal one.
- The website repo is clean by the same scan.

## Not confirmed

- *Session-list shrink misread as a counter reset* (token over-count). Real as
  written, but whether OpenClaw's `sessions list` ever shrinks under normal
  operation was not established. Left as-is; revisit if token figures ever jump.
- *Forged log lines*: an agent that echoed attacker text containing
  `[model-fetch] response … status=429` verbatim to its own stdout could skew
  its **own** owner's dashboard. No path was found where an agent does this, and
  the impact stops at the owner's own numbers.
- *Interleaved stdout/stderr* in `modelCallLog` can splice two partial lines; a
  spliced line fails the parse and is dropped. Under-count only.
