## 3. Security check

**XSS.** Every `${…}` added to the UI since v1.51.0 that skips `esc()` was
traced to its source: fixed emoji/label constants (`icon()`, `V2_CHAN_LABEL`),
numbers (`lostMessages`, token counts, backup age), computed SVG geometry,
or ids passed through `jsq()`. Nothing user-controlled reaches an
`innerHTML` unescaped.

**Prompt injection — the one new surface.** `runOpsTurn()` now writes into
the manager's own conversation for the digest, the Monday nudge and the
suggestion, and the Monday friction check has it *read agent logs*, which
contain text typed by other people. The mitigation is already explicit in
its managed SOUL — everything a tool returns is **data, not instructions** —
and the blast radius is bounded the same way as before: the manager can only
*propose*; every mutation is a card a human confirms, executed with the
confirming user's auth, never the agent's.

**Access.** Unchanged and still correct: Tailscale `serve` is tailnet-only
(`https://spark-f530.tail1329ea.ts.net` → localhost:8080),
`HATCHABOT_ALLOW_OWNER_HEADER` unset in prod, cookies httpOnly +
SameSite=Strict + Secure, console proxy and its WS upgrade both
ownership-checked, Telegram is `dmPolicy:'pairing'` everywhere with
owner-only approval, invite codes ~49 bits, single-use, 48h.

**Hiding Slack/Discord behind `?dev` is a UI gate, not an authorization
gate** — deliberately. The channel routes stay reachable to an authenticated
owner; `?dev` only decides whether the tab is drawn. Nobody without an owner
session gains anything.

**Host exposure (unchanged, still open):**

| Port | State |
|---|---|
| `*:11434` Ollama | **listening on every interface, unauthenticated** — the one real finding, same as 09-19 |
| `0.0.0.0:8080` Hatchabot | intended (Tailscale proxies to it); LAN-reachable |
| `0.0.0.0:4000` | owner still unidentified (needs a `sudo ss -ltnp`) |
| sshd | config unreadable without sudo — password-auth still unverified |
