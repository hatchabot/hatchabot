# Full audit, 2026-10-23 (v2.164.3 → v2.165.0)

Eight reviewers read the codebase in parallel, each one area, read-only, with
the brief in the session's scratch (the method of docs/review-prompt.md: wrong
data, broken promises, security, broken features, regressions, waste; proof
for every finding; a skeptic's look before listing one). Their reports were
then checked here: the top findings were reproduced with throwaway tests or
traced in the code before anything was changed. No live data was read (a
coding session). Verdicts: **fixed** (v2.165.0, with a test in
`test/audit2026-10-23.test.ts` unless noted), **backlog** (real, not done
here; what it would take), **refuted / not verifiable**.

The same release carries the owner's list of updates (Settings → Data, the
Files tab, the console spinner, own bots only, Context now); the CHANGELOG
has both.

## Refuted or not verifiable here

- **ops 1, "main is protected by convention only":** the reviewer's
  `gh api repos/cksci/hatchabot-dev/rules/branches/main` answered `[]`, and
  `…/branches/main/protection` answers 403 to this token. Branch protection
  (five required checks, no bypass) was set up on 2026-10-10 and cannot be
  read with the token this machine has; the owner can confirm it in the
  repository's settings. Not changed.
- **access 8:** a chat-only guest can read `/v1/source*`, `/v1/diagnostics`,
  `/v1/known-problems`, `/v1/runtime`, `/v1/google-oauth/client`,
  `/v1/rebuild-policy` — by design (signed-in-class reads with nothing secret
  in them); noted.
- The lifecycle reviewer refuted five of its own suspicions while checking
  (listed in its report): the backup script's `set -e` fallback, a
  case-sensitive bot lookup, template seed traversal, import tar traversal,
  `config set` without `--replace`.
