# Audit — 2026-09-23 (26th audit)

Asked for: "a full audit, documentation update, security check, and
antagonistic check of everything", at v2.38.0 (43 releases since the 25th
audit at v2.30.1). Seven reviews ran in parallel, each with an attacker's
brief for one area, and every finding was verified against the code before
anything was fixed. Fixed in v2.39.0.

**Verdict: no critical findings; one major (a code risk, not live here), four
medium, and a long tail of low ones and script failure modes — all fixed.
Everything that was attacked and held is listed at the end.**

## Findings and fixes

### Major

- **A "machine login" Claude source mounted the owner's real `~/.claude`
  read-write into their agents** (provision.ts). An agent talked into writing
  a `hooks` entry into `settings.json` there would run it as the owner the
  next time they used Claude Code on the machine — a container escape to the
  owner's account. Not live on the development machine (both subscription
  sources are setup tokens; no agent uses machine login). Fix: no new sources
  of that kind (`HATCHABOT_ALLOW_MACHINE_LOGIN=1` re-enables); the Security
  posture flags an existing one and says to move to a setup token.

### Medium

- **Dockerfile validator bypass by line continuation** (derivedImage.ts).
  BuildKit joins `\`-continued lines before parsing, so `RUN --network\` +
  `=host …` in an imported recipe passed `dockerfileProblem` and reached
  loopback services during the build. Verified with `docker build --check`.
  Fix: validate the logically joined file; refuse `--mount`/`--network`
  anywhere. Also: apt's remove syntax (`curl-`) in package lists, derived
  names the machine would not accept, and a stray image record after a failed
  import build.
- **`dropPin` unpinned before the move could be refused** (routes.ts).
  Fix: unpin last; the agent is busy while its image is built on the runner.
- **Import decompression bomb** (transfer.ts, localDockerProvider.ts). The
  gzipped size was capped (~190 MB) but not what it expands to: a gzip of
  zeros could fill the host. Fix: `HATCHABOT_IMPORT_MAX_GB` (8), counted by
  decompressing once more in the extraction container; the upload ceiling
  lowered to what an import can accept.
- **Internal error text reached the client** on every rethrown
  `ProviderError` (Fastify's default handler serialises `err.message`):
  container names, runner addresses, daemon paths. Fix: an error handler that
  sends `userMessage` or a fixed line, and logs the detail.
- **Login throttle keyed on the socket address**: behind `tailscale serve`
  every client is 127.0.0.1, so ten misses by anyone locked everyone out for
  15 minutes; on a LAN, 10 001 addresses reset the whole map. Fix: the
  forwarded client (trusted only from loopback) and the account under attack
  are counted, oldest entries are evicted.
- **A peer's rehost token was a full owner token**: a hostile peer could read
  bot tokens and credentials or delete agents. Fix: Security → *Token for
  moving agents here* mints a `rehost`-scoped token that opens three routes.
- **Web: *Merge + Push to children* had no confirmation** while the sibling
  Push did. Fix: the same confirmation.

### Scripts (failure modes, verified on this host)

- A shared password with `'` never matched on Linux (systemd's
  `EnvironmentFile` reads `'ab'\''cd'` as `ab''cd'`). The installer refuses one.
- `uninstall.sh` selected every `hatchabot-*` container and volume on the
  machine (a test install beside production), and `--purge` removed the whole
  directory holding the database wherever `HATCHABOT_DB` pointed. It scopes
  to the agents its database knows and removes only Hatchabot's own folder.
- `sort -V` ranks `v2.35.0-beta.1` above `v2.35.0`, stranding a beta tester
  on the prerelease. `~` sorts lowest: `sed 's/-/~/'` before the sort.
- `npm ci` wipes `node_modules` first; a registry outage failed the install
  and the rollback alike, leaving prod with no dependencies and the service
  crash-looping. The working tree is kept aside; refused (2) and
  install-failed (3) upgrades are retried by the follow timers, only a
  release that did not start (1) is remembered.
- `install.sh` moved the checkout before refusing a second install (a
  development clone left detached at the stable tag); no root check; the
  "install a second one" advice would repoint the one service. All three fixed.
- `install-service.sh` offered to restart the user manager from a desktop
  session, which kills the session mid-install. Offered only over ssh/console.
- Follow timers had no PATH (an nvm node is invisible to the user manager);
  `link-cli.sh` rewrote `~/.npmrc` on any failure; `.env` was created with the
  umask before `chmod 600`.

### Low (fixed)

A member of someone else's agent saw the owner's host paths, env-var names
and the gateway port; registering a peer accepted loopback/link-local URLs and
echoed the upstream status (a port scan from the server's vantage point); the
"private" model-server allowlist included `169.254.*` and `*.internal` (the
cloud metadata service); the ops door ran unbounded JSON-RPC batches
concurrently; identity mode honoured a disabled local account's token; the
inbox accept route built a provider for an arbitrary host id before checking
ownership; two concurrent console opens spawned two SSH tunnels and none was
killed at exit; the default image was looked up once per agent (45 docker
calls in a burst) on every list and sweep; the recovery code stayed in the
DOM after its dialog closed; removing a data source had no confirmation;
`textContent` double-escaped a host error; a `target=_blank` without
`noopener`.

### Documented, not changed

- The doorman listens on both its interfaces; the per-agent key still gates
  the door, so this is defence-in-depth only.
- The management agent's `read_result` resolves DNS twice (rebinding could
  reach a loopback GET, bounded to 12 k chars of an unauthenticated route).
- Fleet Gemini/Brave keys are injected into every agent (a stated design; the
  posture view already says so).
- The agent gateway token is placed in the console's new-tab URL (browser
  history only).
- On Docker Desktop a container's request to `host.docker.internal` arrives
  from loopback, so during the accounts-mode first-run window (no account
  yet) an agent could create account #1 without the setup code. Linux is not
  affected; the window closes at the first account.
- Agent caps are check-then-act across awaits on clone/derive/import (ten
  concurrent clones can pass a cap of ten).
- Unpinned network code in `install.sh` (`get.docker.com`, NodeSource).

## Attacked and held

- **Sign-in bypass**: the exempt-path lists of all three modes checked against
  every registered route; each exempt route authenticates in its handler.
  Session cookies bind to the password hash, use `timingSafeEqual`,
  `SameSite=strict`; single-use invite/claim/recovery codes burn on use.
- **Ownership**: every by-id mutating route uses `ownedAgent`; host-level
  surfaces use `ownsLocalHost`; proposals, peers, mesh, classes, connections
  check `ownerId`; the internal principal needs a per-process secret and a
  loopback peer.
- **Injection**: every docker/ssh/tar call is argv-based; slugs, pairing
  codes, image refs, network names, package names, git URLs, env names are
  regex-gated; file content travels base64; paths through `JSON.stringify`;
  `sshTarget` refuses leading `-`.
- **XSS**: 225 sinks traced; every server/user string passes `esc()`/`jsq()`;
  `href`s are server-built `https://` links; no `postMessage` listeners; the
  service worker never caches `/v1/*`; `toast()` uses `textContent`.
- **Mounts**: shared paths pass realpath/symlink/ancestor checks covering the
  docker socket, `~/.ssh`, `~/.config`, the data dir; a cross-owner
  machine-login selection never mounts.
- **Untrusted archives**: manifest schema, slug re-slugification, reserved env
  names, the recipe rules (own FROM/USER, mounts, foreign names) — and now the
  joined-line rule and the size quota.
- **Races**: export, rebuild, move, migrate, archive, delete hold or wait on
  the busy flag; rollback paths leave nothing behind.
- **Scripts**: self-replacing scripts run from private copies; backups prune
  only after a full success; dirty checkouts are refused; exit codes reach
  the timers; no script prints a secret.
