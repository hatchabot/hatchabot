# Audit — 2026-09-06 (11th audit): the v0.106→v0.112.1 surface

Scope: everything shipped since the 10th audit's fixes (v0.106.0) — the entire
platform-managed Google connections subsystem (OAuth, token vault, credential
materialization into containers), the archived-agent inspector (volume reads +
untrusted session parsing), the bot inventory (decrypts every token), recycled-
bot changes, rich-messages + default-source config writes, the OAuth-callback
auth-exemption, restart.sh, and the 657-line UI restructure.

Method: five parallel adversarial reviewers (Google-connections security,
inspect+bot-inventory, auth/routes/restart, store/provision/config, web UI) +
own live-state pass. Every finding verified against code before fixing. All
fixes shipped in v0.113.0.

## Headline
No critical or major defects. Both dedicated security reviewers cleared the
OAuth subsystem, the auth-exemption, the token-decrypting inventory, and the
volume-reading inspector; the web reviewer found no XSS and no dead buttons
across the UI diff. The one authz gap was a MEDIUM.

## Fixed (v0.113.0)

**Medium**
1. `defaultSource` (the installation-wide default AI source) was settable by
   ANY profile-owner, not just the host owner — a co-tenant could clear/override
   the household default and redirect where every other owner's new agents
   silently land. Now `ownsLocalHost`-gated (matches google-oauth client &
   bot-inventory; contrast mgmtLlm/shared which are legitimately per-owner).
   Regression test added.

**Minor / hardening**
2. `materializeConnection`: `conn.email` reached a double-quoted bash context via
   `JSON.stringify` (which does NOT neutralize $ / backtick / "). Google-verified
   emails are safe, but that assumption is no longer the only defense — regex +
   length validated before the `gog auth import` line (matches dematerialize).
3. OAuth callback `page()` helper now escapes its own arguments — a future caller
   can't reintroduce XSS by forgetting to escape.
4. `/connections/google/start`: a non-array `services` with a truthy `.length`
   (e.g. a string) TypeError'd → 500; now shape-checked.
5. Bot inventory getMe was serial (N × 6s timeout) — a slow Telegram with ~40
   bots could stall the admin request minutes. Now bounded-concurrent (8-wide).
6. Recycled-bot announcement (up to 64 sends) + surface-reset ran sequentially
   on the awaited lease/provision path — a Telegram slowdown during a recycle
   could stall a rebuild ~5 min. Sends now run concurrently (worst case one
   timeout).
7. Inspector file cap sliced on JS chars not bytes (multibyte imprecision) →
   byte-accurate; `maxTurns` floored to an integer for `tail -n`.
8. `OAuthStateJar` gained a 256-entry hard cap on top of its TTL sweep.
9. Web: `openInspect` gained the stale-render guard its sibling `renderConnections`
   has — opening one archived agent then another can't cross-paint.

## Backlog (verified open, ranked)
1. `deleteConnection` dematerializes only from RUNNING agents; a connection
   attached to a STOPPED/archived agent leaves its token file on the volume
   (the Google revoke, which runs regardless, neutralizes it unless Google is
   also down). Volume-side removal for stopped agents would close it fully.
2. `adoptLocalOwnerData` re-keys agents/profiles/hosts/etc from the bootstrap
   owner but NOT the `connections` table (latent — this box is past adoption;
   joins the known adopt-gap list with mgmt_heartbeat/telegram_pool.owner_id).
3. `.env.mgmt` is read by a relative path in bot-inventory — works under the
   systemd unit's WorkingDirectory, fragile if launched elsewhere.
4. inspect routes have no agent-state gate; a DELETED tombstone's volume (if it
   survived delete) is still readable by its owner. Owner-only, low.
5. attach-picker load is fire-and-forget with a swallowed catch — silent stale
   UI on a transient error (trivial).
6. Carried from prior audits: CLI prompt injection boundary; 3 diverging .env
   parsers; shell-quoting hardening; pre-production gates before untrusted users.

## Live state (verified, read-only)

honored, all agents on the managed rich-messages default. Service logs quiet
